## WHY-IT-STALLED

Six pieces of evidence, from strongest to weakest.

**1. The premise doesn't work, and he would have found out on his first real run.** Everything downstream — `extract`, `extract-top`, and the frame supply for all three vision analyzers — depends on `detect_scene_changes`. Scene-change detection is the wrong algorithm for continuous first-person gameplay: measured **0 detections** on a 90s continuous clip *and* on a clip with 5 hard cuts. So `valclips extract` returns the first 35 seconds of every clip, dressed up as `activity: 50%`. There's no way to run that on ten real clips and not notice. The `# For now just take the first max_length seconds` stub (`extractor.py:53`) is the note he left himself and never came back to.

**2. Five analyzer backends for one job = thrashing on the hard part.** `ai/local_analyzer.py` (549 lines), `gemini_analyzer.py` (318), `ffmpeg_analyzer.py` (255), `claude_analyzer.py` (164), `stub.py` (19). The `analyze` command carries **11 flags** (`cli.py:412-422`) disambiguated by an if/elif ladder (`cli.py:445-468`) with two independently-derived booleans, `is_heuristic` and `is_vision` (`cli.py:503-504`). That's indecision encoded as CLI surface. Meanwhile `db.py` picks a winner behind his back: `get_insights` filters `ai_agent='gemini'` in all 7 aggregates (`db.py:723-787`) while `CLAUDE.md:13` calls the *local* analyzer "Primary." Follow the README and the insights page is blank.

**3. Abandoned experiments left in place.** `ai/highlights.py:33-40` builds an entire `ffprobe -f lavfi` command and then discards it — `:43` reassigns `cmd` outright, with the comment *"Alternative approach using ffmpeg filter that's more reliable."* Dead code from an approach he tried, ditched, and didn't delete. The `-vsync` flag at `:47` is also deprecated in current ffmpeg (warns on every invocation).

**4. The commit shape says "scaffold, then stop."** 7,303 lines in one initial commit on 2026-02-24 (a single generated skeleton, not incremental work), a CLAUDE.md six hours later, then one 2-line security fix from a PR review on 2026-03-03. **Zero feature commits ever.** Six months of silence. Nothing in the repo reflects a second working session.

**5. The economics never closed.** Reaching the 10 TB library means a full-decode pass — ~26 hours of network transfer at 1 GbE, single-threaded, for a step that produces the wrong answer anyway (#1). Gemini's free tier is quota-limited — the code has a whole `QuotaExhaustedError` propagation path built to abort a batch mid-run (`cli.py:519, 543, 564-574`), which is the fingerprint of repeatedly hitting the wall. Claude Vision on ~18,000 clips × 8 frames would be real money. There was no cheap path to labelling the library, and he owns a DGX Spark that the repo never mentions and never targets.

**6. The plumbing was never finished to production quality.** No prune/reconcile (the index can only grow). No content hashing (dedup guesses from `filename+size+duration`). `export` to stdout has literally never been executed (`cli.py:363` would have crashed immediately). `config.py:29-58` is 23 hand-maintained directory paths including an inline note about a known duplicate at `config.py:56` — manual curation that stops scaling the moment a new folder appears. And the one genuinely finished, genuinely valuable piece — a clean SQLite index with ffprobe metadata, verified fast at 100k rows — is gated behind a `sys.platform == "linux"` check (`config.py:19`) that makes it a silent no-op on the machine he's actually sitting at.

**Bottom line: he didn't abandon a broken indexer. He abandoned a working indexer bolted to a highlight-detection idea that cannot work.** The salvage is `scan`/`db`/`parser`/`thumbnails` — roughly 1,500 lines that run correctly today and are 5 fixes away from being solid. The `ai/` + `extractor` + `highlights` layer (~1,200 lines) is the part to throw away.
