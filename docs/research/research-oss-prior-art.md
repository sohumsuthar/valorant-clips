### Crispy — exact technical facts (verified by reading the source)

- **`crispy-api/api/tools/AI/network.py:8-10`** — the "neural network" is a hand-written numpy MLP, no PyTorch/TF:
  ```python
  NetworkResolution = {
      SupportedGames.VALORANT: [4000, 120, 15, 2],
  ```
  Sigmoid activations (`scipy.special.expit`), manual backprop in `_train()`, weights saved as a pickled `.npy` (`crispy-api/assets/valorant.npy`, 3,855,090 bytes ≈ 4000·120 + 120·15 + 15·2 float64s). Class-imbalance handled by literally dividing the error by 5 (`# five times more likely to be not be kill`).
- **`crispy-api/api/models/highlight.py:212`** — the Valorant crop is `Box(61, 801, 122, 62, 0, stretch)`, and `Box.__init__` (`highlight.py:47-49`) does `self.x = half - x + shift_x` with `half = 720 if stretch else 960`. So the crop is the **absolute pixel rect x∈[899,1021], y∈[801,863]** — the kill-confirmation banner under the crosshair, assuming a **1920×1080** frame.
- Input to the net is a 50×80 RGB composite of FIND_EDGES + flipped EDGE_ENHANCE_MORE crops (`extract_valorant_images`, `highlight.py:176-213`) — 50·80 = 4000, matching the input layer.
- **Resolution fragility is confirmed by its own issue tracker:** #41 "Unable to Identify and Create Segments with non-standard resolutions and Modified HUD positions", #51 "wont create segments (i use 5:4)", #59 "crispy downscales resource footages from 1440p to 1080".

**Verdict on crispy:** the *pipeline* (fps-sample → fixed crop → binary classifier → temporal merge with `second-before`/`second-after`/`second-between-kills` → cut+concat) is correct and worth copying wholesale. The *model* is a 2022-era toy that a 30-line PyTorch CNN or a fine-tuned YOLO-nano beats outright, and the *crop* must be made resolution-relative.

## RIOT-API-ECOSYSTEM

Three distinct layers. Only one is usable, and it is nearly useless for a years-deep archive.

### 1. Official Riot API (`VAL-MATCH-V1`)
- `https://developer.riotgames.com/apis#val-match-v1`
- **Personal and development keys have NO access to the VALORANT API.** Personal Key Applications are not supported for VAL. You must build a working prototype and apply for a **production key**.
- **Practical verdict: dead end for a personal project.** Do not plan around it.

### Local log files — a dead end
Valorant's `%LocalAppData%\VALORANT\Saved\Logs\ShooterGame.log` contains the **client version and shard** and is used by third-party tools for exactly that. ### ShadowPlay metadata
**Nothing reads ShadowPlay metadata, because there is none to read.** Searches for `shadowplay clip`, `nvidia highlights sdk`, `geforce experience metadata` returned only compressors, trimmers, and Discord uploaders (all ≤2★). NVIDIA encodes the game name and capture time into the **filename**, not into mp4 boxes. Sohum's `src/valclips/parser.py` already exploits this and is the correct approach. Valorant never integrated the NVIDIA Highlights SDK, so there are no auto-generated highlight markers to recover.

### Compute reality check
`daseyun/valorant-timestamp-finder`'s README gives the only published benchmark: **27 min of footage → 70 s** (~23× realtime) with plain OpenCV HSV thresholding, single-threaded, on 2022 consumer hardware. 10 TB of ShadowPlay mp4 at 30-80 Mbps is roughly **300-800 hours of footage** (10 TiB = 8.8e13 bits; ÷30 Mbps = 814 h, ÷80 Mbps = 305 h). At 23× realtime that is **13-35 single-threaded CPU-hours** — a few hours with 8-16 workers, and far less with NVDEC on the GB10. **The bottleneck is not compute, it is reading 10TB off `truenas-scale` over the network** (~22 h at 1 Gbps, ~2 h at 10 GbE). Any design that streams the whole archive twice is wrong; do one pass that extracts frames + embeddings + events together.

## Verified hard facts

- Flowtter/crispy (https://github.com/Flowtter/crispy) is the ONLY open-source project that detects kills in first-person Valorant footage end-to-end: 156 stars, MIT, last commit 2025-03-20, last release 1.1.4 on 2024-11-01, 0 open issues — effectively dormant for 18 months.
- Crispy's Valorant 'neural network' is a hand-written numpy MLP with layer sizes [4000, 120, 15, 2] and sigmoid activations, defined at crispy-api/api/tools/AI/network.py:8-10, with manual backprop and class imbalance handled by dividing the error by 5 — no PyTorch or TensorFlow anywhere.
- Crispy's Valorant crop is Box(61, 801, 122, 62, 0, stretch) at crispy-api/api/models/highlight.py:212, and Box.__init__ (highlight.py:47-49) computes x = 960 - 61 = 899, so the crop is the absolute rect x in [899,1021], y in [801,863] — hard-coded to a 1920x1080 frame (1440 half-width in 4:3 stretch mode).
- Crispy's own issue tracker confirms resolution fragility: #41 'non-standard resolutions and Modified HUD positions', #51 'wont create segments (i use 5:4)', #59 'crispy downscales resource footages from 1440p to 1080'.
- SphinxNumberNine/valoscribe (14 stars, MIT, last commit on main 2026-01-13, pushed 2026-02-08) targets the professional SPECTATOR/broadcast HUD (config/champs2025.json, 10-player state bars), not the first-person player HUD, so its detectors and templates are not directly reusable on ShadowPlay clips.
- ydc-p-dev/valorant-ocr-benchmark (6 stars, last commit 2026-03-23) is the closest first-person killfeed parser (MSS capture + OpenCV HSV row detection + Tesseract/EasyOCR + masked-NCC weapon templates, exposes parse_killfeed_image()) but has NO LICENSE file, making it legally unusable.
- daseyun/valorant-timestamp-finder (3 stars, no license, last push 2022-05-22) is the source of the HSV constants already present in Sohum's repo at ~/Documents/GitHub/valorant-clips/src/valclips/ai/local_analyzer.py:137-160, and its README gives the only published benchmark: a 27-minute recording processed in 70 seconds (~23x realtime).
- The entire Valorant-CV-on-recorded-footage category totals roughly 180 GitHub stars across all repos, while Valorant aimbot repos total over 2,900 (RootKit-Org/AI-Aimbot 2,069 stars — now ARCHIVED 2025-10-09; zeyad-mansour/lunar 439; ai-aimbot/AIMr 385).
- Riot's official VAL-MATCH-V1 API is inaccessible without a production key: personal and development keys have no VALORANT access, and Personal Key Applications are not supported for VALORANT.
- The unofficial local client match-history endpoint is GET https://pd.{shard}.a.pvp.net/match-history/v1/history/{puuid}?startIndex=&endIndex=&queue=, requires 4 headers (X-Riot-ClientPlatform, X-Riot-ClientVersion, X-Riot-Entitlements-JWT, Authorization: Bearer) sourced from a running local Riot client, and defaults to endIndex=20.
- techchrism/valorant-api-docs (593 stars, MIT) has been dormant since its last commit on 2024-04-20, though the hosted docs at https://valapidocs.techchrism.me remain the canonical reference and the underlying API is still in active use by zayKenyon/VALORANT-rank-yoinker (564 stars, commit 2026-05-21) and Soneliem/WAIUA (180 stars, pushed 2026-09-12).
- colinhartigan/valclient.py (80 stars, MIT) is ARCHIVED with its last commit on 2022-07-16, and HeyM1ke/ValorantClientAPI (414 stars, no license) last committed 2021-11-10 — both are reference-only, not buildable dependencies.
- HenrikDev's unofficial-valorant-api (554 stars, no license file, last commit 2026-05-01) enforces 250 requests per 2.5 minutes IP-based, issues a 'Basic' key instantly and an 'Enhanced' key on application with a 1-2 week response SLA, and exposes stored-matches and stored-mmr-history endpoints backed by its own database.
- Immich (113,962 stars, AGPL-3.0, commit 2026-09-13) generates ML embeddings from the generated video THUMBNAIL only — its FAQ states facial recognition 'operates on the generated thumbnail' and that 'Scanning the entire video for faces may be implemented in the future' — so it produces one embedding per video file and cannot locate a moment inside a clip. PhotoPrism (40,187) and LibrePhotos (8,069) share this limitation.
- The only high-traction frame-level video retrieval project is HKUDS/VideoRAG (3,365 stars, KDD'2026 paper code), whose last commit was 2026-03-18 with 21 open issues and no packaging — research code, not a deployable system.
- Segergren/Segra (209 stars, GPL-2.0, last commit 2026-09-10) is the most actively maintained open-source gaming clip recorder with auto-highlights, but supports only CS2, League, Dota 2, PUBG, Rocket League, Rust, Minecraft, RuneScape: Dragonwilds, War Thunder and GTA — Valorant is explicitly absent, and no Valorant issue has ever been filed against the repo.
- Segra contains a reusable generic OCR event-detection base class at Backend/Games/OcrIntegration.cs (Windows.Media.Ocr, configurable CropRegion + OcrKeyword list + per-event cooldown + exclude-fragments + 250ms poll), but it runs against the live OBS GameCaptureSource during play, not against recorded files, and is Windows-only C#.
- ShaneIsrael/fireshare (1,475 stars, GPL-3.0, commit 2026-09-10) is the most-starred self-hosted gaming clip library, with a companion ShadowPlay uploader (J-Stuff/fireshare-agent), but it has no AI, no semantic search and no event detection.
- No open-source project reads ShadowPlay/GeForce Experience mp4 metadata, because NVIDIA encodes the game name and capture time into the FILENAME rather than into mp4 metadata boxes — searches for 'shadowplay clip', 'nvidia highlights sdk' and 'geforce experience metadata' returned only compressors, trimmers and Discord uploaders, all at 2 stars or fewer.
- Valorant's %LocalAppData%\VALORANT\Saved\Logs\ShooterGame.log contains only the client version and shard (used by third-party tools for exactly that) and carries no kill, round or scoreboard events; GitHub searches for 'valorant log parser' and 'ShooterGame.log valorant' returned zero repositories.
- Public Valorant killfeed training data on Roboflow Universe totals about 1,213 images across three sets: valorant-kills (1,018 images plus a pretrained model), VALORANT Killfinder (168 images) and Exorb valorant-kill-feed (27 images).
- valorant-api.com is a free, keyless, community-maintained static asset API covering agents and abilities, weapons, skins/chromas, buddies, player cards, titles, maps, gamemodes and seasons — the canonical free source of icon templates for template matching, and explicitly non-official/not endorsed by Riot.
- As of giorgi-o's writeup last updated April 2026, Riot has issued no guidelines on third-party Valorant tools since its vague June 2022 warning tweet, no widespread bans of local-client-API users have occurred, and injecting requests into the local Riot.exe API does not touch Vanguard — while memory reading remains banned and Vanguard-detected.
- 10 TiB of ShadowPlay mp4 corresponds to roughly 300-800 hours of footage (8.8e13 bits divided by 30-80 Mbps), which at the 23x-realtime OpenCV benchmark is only 13-35 single-threaded CPU-hours, making network read bandwidth off the NAS (~22 h at 1 Gbps) the real bottleneck rather than compute.
- Maintained, permissively-licensed building blocks all exist and should be reused unmodified: mlfoundations/open_clip (14,137 stars, commit 2026-09-08), Breakthrough/PySceneDetect (5,174 stars, BSD-3-Clause, commit 2026-09-12), SYSTRAN/faster-whisper (25,366 stars, MIT, commit 2026-09-13), m-bain/whisperX (24,010 stars, commit 2026-09-13) and HaveAGitGat/Tdarr (4,316 stars, commit 2026-09-10) for bulk transcoding.
- akamhy/videohash (382 stars, MIT), the standard perceptual video-hash library for near-duplicate detection, has not had a commit since 2022-05-29 (last push 2024-07-12) and should be copied rather than depended on.
- Sohum's existing repo already contains a scale-aware Valorant HUD region map at ~/Documents/GitHub/valorant-clips/src/valclips/ai/local_analyzer.py:11-26 (killfeed top-right 1275-1900 x 96-496, round score top-center, alive indicators, minimap, abilities, health/shield, kill banner, round outcome text) using sx/sy scale factors — strictly better than crispy's hard-coded 1080p box.
